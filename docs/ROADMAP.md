# Aurora roadmap

## M7 3D groundwork

The 3D drop test runs three dynamic cuboids against a fixed platform. The window, screenshot, and headless paths share the same 60 Hz simulation. The GPU path renders the physics poses through a perspective camera, directional lighting, instancing, and a depth buffer. Rapier is the default. A feature-enabled build can also select Jolt.

```bash
cargo run --locked --bin aurora-player -- --3d
cargo run --locked --bin aurora-player -- --3d --headless --frames 240
cargo run --locked --bin aurora-player -- --3d --capture-after 240 --screenshot /tmp/aurora-3d.png
cargo run --locked --bin aurora-player --features physics-jolt -- --3d --physics-backend jolt
```

Building the optional Jolt backend requires CMake and a C++ toolchain. Each backend owns its solver state. Tests compare settled poses with tolerances across solvers and repeated results within a solver when required. The Jumpy Bird golden continues to cover the 2D runtime.

## Implemented authored workflows

- **Authored 2D physics.** Scene and prefab nodes can own Fixed, Kinematic, or Dynamic Rapier bodies with solid or trigger box, circle, and polygon colliders. Fixed-tick contacts use enter/exit handling and Inspector controls; existing overlap sensors remain supported. Scripted bodies can set linear velocity.
- **2D visuals and editor.** Runtime Text/Rich Text and custom font rasterization, particles, tile maps, atlas sprites, and nine-slice panels are editable in the Inspector and rendered in Scene and Play views. Grouping preserves sibling poses. Timeline curves support key dragging, Step/Linear/Cubic interpolation, and cubic tangent editing.
- **Combined 2D/3D projects.** The project manager offers 2D, 3D, and Jumpy Bird starters. Scene assets record a 2D or 3D authoring mode; both can mix pixel-space and spatial nodes. Authored spatial transforms, cameras, directional lights, cube materials, cuboid physics, and glTF mesh plus base-color material import are wired through the editor and player.
- **Scene cameras and play scope.** Each scene records an `auto`, explicit-camera or `flat` camera choice; the editor picker accepts a dropped Camera 3D node, and Camera view locks the Scene view to that camera's framing. Protocol 20 lets scripts switch cameras at runtime. The toolbar's Play switch stages just the open scene or the whole project, and Project Settings offers a scene picker with drag-and-drop.
- **3D authoring depth.** The Scene view uses an orbitable perspective camera with projected selection and X/Y translation, local-Z rotation, and uniform scale tools. glTF import preserves UVs, writes base-color textures beside the prefab, shades metallic/roughness materials, imports step and linear animation samplers into prefab clips, and bakes skins at their rest pose with inverse bind matrices and joint transforms. Spatial clips carry XYZ translation, rotation and positive scale channels, survive prefab instantiation by rebasing prefab-local track indices, and drive authored nodes through the same `Playback` used by the player and editor Play. Rotation keys are decomposed from quaternions to Euler degrees and blended per axis, which is a documented lossy approximation of spherical interpolation. Dynamic cuboid physics still overwrites animation on the same tick. Protocol 16 adds a real Z slot to the script envelope, so scripts can set velocity through `this.body3d`, read spatial transform streams through `NodeRef.z`, and receive 3D contact callbacks. The Scene view follows scene content with an adaptive ground grid, axis widget, camera pan/dolly and axis-picked transform handles; 2D nodes render as a screen-space GUI over the 3D world. Authored physics supports Fixed, Kinematic and Dynamic bodies with box, sphere, capsule, mesh and convex colliders, trigger overlaps, editable friction/restitution, scene joints and an optional Jolt backend; the script peer handle reports whether a contact came from a trigger.
- **Jumpy Bird.** The authored scene and TypeScript sample are editable in the native editor. The fixed 600-tick replay remains byte-stable against its committed snapshot. [Build Jumpy Bird in the editor](JUMPY_TUTORIAL.md) walks through creating the scene tree, pillar prefab, frame and sound banks, wing animation, component binding, and Play verification from a blank 2D project.
- **Scripting and export.** Runtime component addition and removal, pointer hit testing, richer input packets, project-wide prefab catalogs, a global `assetManager`, bundle-wide preload/load progress, cancellation, and isolated per-component handles are implemented. The development and native backends share the same TypeScript API, and `tools/test-export.sh` exports a native-script project, verifies its manifest and launcher, and runs the bundled game headless.
- **Spatial physics depth.** Kinematic bodies, box/sphere/capsule/mesh/convex colliders, trigger overlaps, editable physics materials, fixed/ball/hinge/slider joints, angular velocity, world transform streams, raycasts, box shape casts and box overlap queries are implemented with backward-compatible scene fields. Scripts control linear and angular velocity on dynamic and kinematic bodies and receive solid, trigger, raycast and overlap events. Joints are authored in the Inspector's **Physics 3D / Joints** section, saved in scene JSON, and rebased when a prefab instance is created. Protocol 19 adds the overlap and shape-cast requests; scripts built for older protocols must be rebuilt. The optional `physics-jolt` backend now drives authored scenes through `--physics-backend jolt` with parity for bodies, colliders, materials, sensors, velocities, contacts and pose writeback. Jolt does not yet support authored joints or host queries, and rejects mesh/convex colliders on moving bodies or sensors with a clear error; those operations remain on Rapier.
- **On-demand asset import.** Protocol 18 imports PNG, WAV/MP3 and prefab files from project-relative paths with one shared reference-counted handle space. `Resources` and `assetManager` expose `*File` loaders and `releaseAssetHandle`; dynamic clips play through the SFX bus and dynamic prefabs instantiate through the scene prefab catalog. Catalog loads still resolve only scene-registered banks and the project prefab catalog. Exports stage every supported project asset at its project-relative path, so on-demand loads resolve without an authored scene reference.

## Remaining work

- **Distribution and platform verification.** Engine releases, builder images, and game packages remain separate products. The tagged release workflow builds desktop engine archives and checksums. Editor export creates a locally runnable host-OS folder with a launcher and integrity manifest, and now accepts an explicit `--export-target` and `--player` so cross-target packages stamp the requested target. `aurora build` supports local Docker/Podman builds, ephemeral images and build metadata, and can consume a verified `--template` archive: `tools/package-target-template.sh` produces a hashed per-target player/launcher bundle, and the CLI verifies per-file and bundle digests before caching it. Windows now has a named-pipe script transport, target-aware stamping and a Windows native-script FFI manifest; Android has a NativeActivity cdylib shell, manifest, Gradle files and an APK build script; Web has a wasm-bindgen canvas shell driven by `requestAnimationFrame`. All three remain **blocked** in `aurora targets` because no Windows std/MinGW/scriptc, Android SDK/NDK/device, or wasm toolchain/browser is available here, and their script runtimes are scriptless-first. macOS stays host-only: `aurora build --target macos` packages a `.app` on an Apple-branded host with optional signing/notarization; no macOS container image is supported under Apple's SLA. Hosted project builds, update channels, CI activation and image publishing still require external infrastructure and authorization; the package workflows remain disabled. Docker daemon access is denied on this host, so the container smoke test cannot run here. Local Linux package, editor export, script builds, Jolt and Rust checks passed; native Windows/macOS, Android devices, Web browsers, container builds and alternate GPU drivers remain unverified. See [the build package model and platform matrix](BUILD_PACKAGES.md).
