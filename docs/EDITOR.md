# Aurora editor

Build both binaries with `cargo build --locked --workspace`. Launch `target/debug/aurora-editor` to open Projects. On first launch, choose a default projects folder. The suggestion is `~/Aurora`. **Settings** on the Projects screen can change it later.

| Platform | Preferences file |
| --- | --- |
| Linux | `~/.aurora/config` |
| Windows | `%APPDATA%/Aurora/config` |
| macOS | `~/Library/Application Support/Aurora/config` |

**New Project** asks for a name, parent folder, and starting scene type. Choose **2D** or **3D**; either project can contain both pixel-space and spatial nodes. **Create & Edit** creates a fresh subfolder containing `assets/`, `main.scene`, and TypeScript support. **Import Project** opens an existing project folder or scene. Opening a project folder restores the last scene you were editing; when no cached scene exists it opens the configured default, or `main.scene`. **Project → Project Settings** stores that default scene as a path relative to the project root in `.aurora/project-session.json`. Browse, type a path, or drop a folder or scene onto the Projects screen. Search Recent and double-click an entry to open it. Existing projects with legacy scene and prefab extensions still open under their current filenames. Forget removes it from the list and keeps its files. On Linux, Recent retains its catalog in `$XDG_DATA_HOME/aurora/projects.json`, defaulting to `~/.local/share/aurora/projects.json`.

## Project TypeScript SDK

The editor installs `.aurora/index.d.ts`, its SDK declaration modules, and `.aurora/tsconfig.json`. The root `tsconfig.json` extends Aurora's generated config and resolves `import ... from "aurora"` for type checking, including the `property` decorator. Previous generated SDK paths continue resolving through the current declaration. If the project already has a custom `tsconfig.json`, keep it and add `"extends": "./.aurora/tsconfig.json"` or an equivalent `paths` mapping for `aurora`.

Projects without generated files receive the current SDK on open. If the generated SDK records a different editor version, **Update & Edit** confirms replacement before the project opens. Keep a backup or commit before updating scripts for an SDK change. The editor refreshes generated files in place and preserves the root config and source files. On each open it also refreshes generated contents changed within the same editor version. SDK files and script preview wire bindings are generated inside the editor without invoking Cargo or TypeScript.

Use `target/debug/aurora-editor --project /path/to/project` to open the editor directly. This also accepts individual scene and prefab files. A directory without a scene opens an unsaved Canvas in this direct launch mode. Ctrl+S saves scene changes.

- Select nodes in the hierarchy or click sprites in the Scene view. Double-click a text node in Scene view to edit its first text run in place; press Escape or click outside it to finish. Use Up and Down in the focused tree to move through visible rows, F2 and Enter to rename, and Ctrl+D to duplicate. Drag a node onto another node to reparent it, or onto the root drop target to unparent it. Use the context menu to save a subtree as a prefab. Double-click a prefab asset to edit its isolated tree.
- Click a Built-in Node Library tile to add it under the selected node; with no selection it becomes a child of the scene root when one exists. Drag a tile into the Scene view or Scene Tree to choose its placement.
- Drop PNGs onto the app to import them. Drag a PNG onto a node to attach or replace its sprite, or drop it into the viewport to place a new sprite. In Scene view, drag a selected 2D node to move it and drag a square corner handle to scale it without using Inspector fields. Hold or release Ctrl during a drag to toggle uniform scaling live. Text handles increase or decrease styled font sizes as needed and compensate the node scale to keep glyphs crisp. The viewport also supports right-drag panning, scroll zoom, rulers that adapt to the zoom, and anchor markers. Click a sprite to select its drawn bounds or click empty space to clear selection.
- Create a TypeScript component from the Assets menu. The template imports `aurora` and uses `@ccclass` and `@property`. See the [scripting guide](SCRIPTING.md). Drag its asset onto a node or choose it from Add Component. The inspector uses metadata to accept node and prefab reference drops and persists the resulting values. Fields declared with a component class, such as `@property(Health)`, show a searchable list of the document's components and store the referenced node and component name. Audio clip and sprite frame fields list the scene's registered sound and frame-bank assets.
- In Timeline, create a clip, choose a node and transform channel, and add keys at the cursor. Edit values, key times, and cubic incoming/outgoing slopes in the track rows or drag keys on the curve editor. Choose Step, Linear, or Cubic interpolation. Preview with the transport or scrub the time ruler. Autoplay selects the clip used on entering the scene.
- Play passes the project's `.aurora/game-config.json` and a per-user secrets file outside the project to the child player; see [global config and secrets](SCRIPTING.md#global-config-and-secrets). Play bundles all components attached directly to the open scene for Bun or Node and starts a separate player process. The player renders using offscreen wgpu, with the scene’s aspect ratio and a 960-pixel cap on the longest edge and publishes complete RGBA frames at up to 20 Hz. Game view scales that texture to fit its dock. The console receives child diagnostics. Changes to watched TypeScript and prefab files rebuild the preview. TypeScript changes also refresh Inspector metadata. Failed rebuilds leave the previous running preview available. Pause and Stop control the current child process. F5 starts Play and F8 stops it.
- The default layout follows Godot's editor: **Scene Tree** and **Node Library** on the left, **Viewport** with **Output** and **Animation** below it in the centre, and **Inspector** above **FileSystem** on the right. A run bar under the menu row collects Play, Pause/Resume and Stop. **Layout → Godot Layout** reapplies this arrangement; saved layouts from earlier versions can be replaced with it. Layout is stored per project root in `.aurora/layout.json`.
- **File → New Scene** opens the same scene dialog as FileSystem's **New Asset → New Scene**, and opens the created scene once saved. Scenes opened from inside a project keep that project's root and FileSystem location. Creating another scene, switching scenes or projects, or deleting the open scene with unsaved changes shows an **Unsaved changes** dialog with Cancel, Save and Discard instead of an error.
- Browser and Projects are available in the main menu row. The Node Library's Built-in items wrap into columns to fit the panel width. FileSystem opens at the project root (`res://`), so new scenes and assets default there; a create action from a file's context menu still targets that file's folder. It is a single file pane: the `res://` breadcrumb navigates folders, double-click a folder to enter it, and the search box finds assets recursively anywhere under the project, like Godot's FileSystem dock. The toolbar holds create, search, delete, refresh and list/grid controls; when the dock is narrow, use the ≡ actions menu for the same actions. Click to select one entry; Ctrl-click toggles additional entries and Shift-click selects the whole range from the last ordinary selection to the clicked entry in display order. The toolbar's delete button removes every selected entry after one confirmation. Right-click never navigates — double-click a folder to enter it — and offers delete first, show in the system file browser, and create a sibling asset.
- Project → Display Settings saves the design resolution and Contain, Cover, or Stretch fit policy in the scene. The Game view forwards key presses and releases, mouse wheel deltas, pointer press, drag and release, and every real multi-touch contact with its own identity. Pointer drags keep the node captured on press, matching the standalone window. Losing window or Game view focus cancels the mouse and all active touches. Space, Up and coordinate-free touch remain available.
- Ctrl+S saves the current scene and Ctrl+O opens the project browser. F2 renames the selected node, Ctrl+D duplicates it, F5 starts Play, and F8 stops Play. Use `--screenshot PATH` to capture the Projects screen. Add `--project PATH` for the editor and `--play` to wait for an embedded game frame.

Engine releases contain the editor/player for supported desktop hosts. **Export** produces a locally runnable folder with the scene bundle, a matching `aurora-player`, a `run-game` launcher and `export.json` integrity metadata. The editor also accepts `--export-target` and `--player` so a build pipeline can stamp a cross target and substitute a verified target runtime; the default remains the local host. Scripted builds run on Linux and macOS through the Unix transport; a Windows named-pipe transport is implemented but unverified on Windows. Target templates can be produced and consumed with checksum verification, but hosted builds remain future work. See [the platform build package status](BUILD_PACKAGES.md).

The Node Library includes Empty Node, Sprite, Text, Rich Text, Particles, Tile Map, Atlas Sprite, Nine-Slice, spatial 3D nodes, and project prefabs. Configure 2D visuals in the Inspector; text supports multiple styled runs and project TTF/OTF fonts. The Scene view previews these nodes using the same geometry as Play. Select sibling nodes in the hierarchy and choose **Group** to preserve their poses under a new parent. See [authored 2D visuals and spatial nodes](SCENES.md#text-particles-and-textured-2d-nodes) for supported formats and limits.

The Scene view has **2D** and **3D** view buttons. Scenes with spatial nodes open in the Unity-style 3D view by default. That view draws an adaptive XZ ground grid with coloured origin axes, a corner orientation widget, and a live X/Z readout under the cursor; the 2D rulers and design frame are hidden. Middle-drag orbits, right-drag pans the camera target, and scroll dollies; **Reset view** restores the default angle and distance. 2D sprites remain visible in the 3D view: they are projected through the same perspective camera at 32 pixels per metre, placed on the `z = 0` plane when the node has no spatial parent, and painted far-to-near because egui has no depth buffer. Choose **2D** to restore the flat design view with rulers, pan and zoom.

Spatial nodes show a wireframe for cubes and imported meshes through the perspective camera. Click a projected shape or node marker to select it. The **Move**, **Rotate** and **Scale** tools now pick an individual axis handle: dragging one axis constrains translation or scaling to that axis, and rotation applies to the picked local axis. With no axis handle, scaling stays uniform and rotation uses Z. The Inspector edits position, rotation, scale, material base color, metallic and roughness, physics body (None, Fixed, Kinematic, Dynamic), collider shape (box, sphere, Y capsule), Trigger, friction and restitution, and camera field of view. Non-cuboid and trigger colliders get a distinct projected outline. Imported meshes shade with their base-color texture when the glTF supplied one. With a spatial node selected, Timeline offers XYZ translation, rotation and positive scale channels alongside the 2D channels; imported glTF clips open with their prefab and keep their tracks when the prefab is saved. Scripts can set velocity on dynamic and kinematic bodies and receive solid or trigger contact callbacks. The Inspector's **Physics 3D / Joints** section edits scene-level constraints between those bodies: pick Body A and Body B from physics-enabled spatial nodes, choose Fixed, Ball, Hinge or Slider, edit each body's local anchor and the joint axis, then add or remove joints. Joint indices follow scene node order and are rebased when nodes are removed; prefab documents do not own scene joints.
