# Authored scenes and prefabs

`.scene` and `.prefab` are UTF-8 JSON documents with a numeric `version` of 1. Older `.aurora-scene` and `.aurora-prefab` files use the same format and still load. Scenes may set `scene_kind` to `two_d` or `three_d`; these are the only modes offered when creating the first scene in a project or another scene asset. If omitted by an older document, the mode defaults to `two_d`. The field is an authoring hint, not a node restriction: 2D and 3D nodes can share a scene. Scenes may also set `camera` to `auto`, `{"node": index}` or `flat`; older documents without it use `auto`. In the editor a scene with spatial nodes uses the 3D view, where 2D nodes are a screen-space GUI over the 3D world; a scene without spatial nodes uses the flat 2D view. There is no view switch. Nodes appear in parent-first order and use zero-based indices. Omit a node's `parent` for a root. Prefabs have exactly one root. A sprite describes a PNG path and a local width and height. Paths resolve relative to the document that declares them. Omitting the whole transform gives the identity pose. Authored positions are in pixels, Y points up, rotation is in radians, and scale is unitless.

The optional `script_prefabs` array lists prefab assets available for script instantiation. Array indices identify these assets over IPC. The player resolves and caches registered prefab data on the first instantiation. Dynamically created roots have separate runtime references, and destroying one invalidates its descendant references. Authored node indices keep their existing meaning.

A scene can append prefab instances. Each instance can attach to an inline scene node. Track targets use the inline nodes followed by the nodes from each instance in authored order. Runtime handles are opaque and are reallocated after a scene change or pool checkout.

Use `SceneFile::capture` or `PrefabFile::capture` with a callback that resolves texture IDs to document paths, then call `save` to write the file. These capture helpers deliberately drop clips. Use `SceneFile::capture_with` or `PrefabFile::capture_with` to retain an authored `animations` list, then call `save`. To edit an existing scene without losing its clips or prefab references, use `SceneFile::load`, edit the document, and save it. See the [gallery scene](../scripts/game-template/scenes/gallery.scene) and [marker prefab](../scripts/game-template/scenes/marker.prefab) for examples.

Editor exports include a matching `aurora-player`, `run-game.sh` (or Windows `run-game.cmd`), and `export.json`, which records the engine version, exporting host target, sorted package file hashes, and a digest over the bundle contents. Run the launcher to start the exported game. The player verifies this manifest when present and continues to accept older bundles that predate it. The output runs on the editor host and is not a cross-compilation template; see [the build package status](BUILD_PACKAGES.md).

## Playback and pooling

A clip describes its sample rate, duration in samples, speed, wrap mode, property tracks, and optional markers. Each track targets one local transform channel and uses strictly increasing keys. Cubic interpolation eases between keys with zero tangents. An autoplay index selects the clip that starts on scene entry. The director can play another clip by index and pause or resume simulation without resetting playback.

Scalar channels `x`, `y`, `rotation`, `scale_x` and `scale_y` address the 2D transform in pixels, radians and unitless scale. The spatial channels `translation_x`, `translation_y`, `translation_z`, `rotation_x`, `rotation_y`, `rotation_z`, `spatial_scale_x`, `spatial_scale_y` and `spatial_scale_z` address a node's 3D component in metres, degrees and positive unitless scale. A spatial channel on a node without a 3D component fails playback; spatial scale keys must be positive. A node that has both components may carry both sets of channels. Animation is applied before physics, so a dynamic cuboid's solver pose overwrites animation on the same tick; animate fixed cuboids or pivots instead.

Scene clips target the flat node order: inline nodes first, then nodes from each prefab instance in authored order. A prefab document may also carry its own `animations`, whose tracks use prefab-local indices. On scene load those tracks are rebased to the instance's position in the scene's flat node order and appended after the scene's own clips, so `Director::play` indexes remain valid. Editor prefab editing preserves prefab clips but does not expose them in the Timeline.

A Rust `NodePool` borrows the owning scene and prefab. `get` checks out a reset subtree, `reset` restores an active instance's authored pose and sprites, and `put` detaches it. The pool rejects a return if the prefab instance's topology changed. A returned instance's handles are stale even if a later checkout reuses its ECS allocations. TypeScript currently controls the director and receives animation events. Prefab instantiation and pooling are available through authored scene references and the Rust APIs.

List scene-local prefab paths in `script_prefabs` to make them available to native or development script entries. The list order determines prefab IDs. Editor preview and native export assemble this catalog from project prefab assets and typed Inspector references. Runtime node and prefab operations are described in [Scripting](SCRIPTING.md).

## Authored 2D physics

Select a node in a scene or prefab, open **2D Physics** in the Inspector and enable **Rigid body**. Choose **Fixed** for scenery, **Kinematic** for an animated platform, or **Dynamic** for a falling object. Choose **Trigger** to report overlap without applying a collision impulse. Enter box width and height, circle radius, or polygon boundary points in world pixels. A polygon accepts 3–128 points in either winding order, including concave outlines. The closing edge is implicit.

A node stores the component as an optional field, for example `"physics2d": {"mode":"dynamic","collider":{"shape":"circle","radius":12.0}}`. The player uses 32 pixels per meter and advances Rapier after fixed updates and animation sampling. Body position follows the scene hierarchy. Collider dimensions are independent of sprite scale, and body angle is the sum of parent and local rotations. A dynamic body needs an invertible parent transform for writing its pose back to the scene.

A component bound to a dynamic body can call the existing SDK’s `this.body.setLinearVelocity(x, y)` in meters per second. The next physics step applies the most recent command. Physics pairs feed the existing collision enter and exit callbacks. Inactive subtrees leave the physics world and start with fresh bodies when enabled. Removing a touching body delivers an exit to its surviving counterpart. Scene changes discard the previous solver and its contact pairs. Existing `gameplay.sensors` keep their rectangle-overlap behavior and may coexist with body contacts.

## Text, particles, and textured 2D nodes

In the Node Library, click or drag **Text**, **Rich Text**, **Particles**, **Tile Map**, **Atlas Sprite**, or **Nine-Slice**. Edit the selected node in the Inspector. Each node uses its existing 2D transform, layer, tint, opacity and visibility. The Scene view shows the same geometry as Play. The timeline cursor can sample particle motion while editing a clip.

- **Text and Rich Text** use the same component. Each run has text, a local pixel size and an RGBA color. Add runs for mixed styling and enter a newline for an explicit line break. Drop a project TTF or OTF on **Drop font** to replace the bundled font. The rasterizer supports kerning. Text uses glyph-by-glyph layout with explicit line breaks.
- **Atlas Sprite** selects one uniformly sized cell by row-major index, starting at the top left. Drop a PNG sheet and set cell size and frame.
- **Tile Map** uses the same atlas indexing. Set the grid's column count, then edit row-major cells, using −1 for empty. The file stores an empty cell as JSON null. Tile dimensions and the output image are limited to 4096 pixels per axis.
- **Nine-Slice** takes four source border widths in left, top, right, bottom order. Set output dimensions in the Inspector to stretch the center and preserve the corners. Transform scaling applies afterward to the entire result.
- **Particles** distributes timed particles around a radial emitter. Lifetime is in 60 Hz ticks, speed is in pixels per second and gravity acts downward. Position, rotation and scale are local to the node.

Resources are document-relative, including inside prefabs. Projects using these visual components require a player and editor that understand the optional `visual` node field. Older scenes retain their original sprite bindings.

### Spatial nodes and 3D scenes

Choose **3D** as the first scene when creating a project to get a pivot, cube, camera and directional light. New scene assets offer **2D** and **3D** only. Either scene can contain both kinds of nodes: 2D nodes become the GUI drawn over the 3D world once the scene has spatial nodes. Add **Node 3D**, **Cube 3D**, **Camera 3D** or **Directional Light** from the Node Library. Use the spatial Inspector to edit translation in metres, XYZ rotation in degrees, positive scale, cube material or physics, and camera field of view. Physics choices are None, Fixed, Kinematic and Dynamic, with box, sphere, Y-capsule, triangle-mesh (fixed only) or convex-hull colliders and a Trigger flag plus friction and restitution. An optional scene-level `joints` array constrains two body indices with `fixed`, `ball`, `hinge` or `slider` kinds, local anchors and an axis. The Inspector's **Physics 3D / Joints** section authors them with node pickers; scene node edits rebase or drop joint endpoints, and prefab joints are rebased when a prefab instance is created. In the Scene view, click a projected wireframe or marker to select it. There are no view buttons: the view follows the scene, so scenes with spatial nodes use the perspective view and scenes without them use the flat design view. In 3D, middle-drag orbits, right-drag pans, and scroll dollies. The **Move**, **Rotate** and **Scale** tools pick an individual axis handle; without a picked axis, rotation uses local Z and scaling is uniform. Play shows shaded geometry with 2D sprites composited on top.

Cameras look down local −Z. The scene-level `camera` field is `auto` (first visible camera in tree order), `{"node": index}` for an explicit Camera 3D node, or `flat` to hide the 3D layer and present the scene as 2D. The selected camera is rebased when nodes are removed, and a script can override it until the scene changes. A unit cube is one metre on each side. Fixed, kinematic and dynamic bodies share the scene's 60 Hz Rapier world. Fixed bodies follow authored transforms; kinematic bodies also follow authored transforms, advance by a scripted velocity, and are not overwritten by the solver; dynamic bodies integrate contacts and gravity and write their pose back to the node. Triggers report overlaps without applying contact forces. Box is the default shape, so older documents keep their cuboids. Use uniform parent scale for a rotating body to keep its shape representable as a collider.

Drop a GLB or glTF file onto the editor window. Aurora creates `assets/<model>.prefab`, which can be opened for editing or dragged from the Node Library into a scene. Buffers can be embedded, stored in the GLB chunk, or kept under the source file’s directory. Import supports indexed and unindexed triangle geometry, local transforms with positive scales, base-color factors, `TEXCOORD_0` texture coordinates, a base-color texture, and metallic/roughness factors. A referenced base-color image is decoded and written as PNG under `textures/` beside the prefab, and the mesh records the relative path. Importing a second time requires a new destination name or deliberate removal of the previous prefab.

glTF animations become prefab clips sampled at 60 Hz. Step and linear samplers map to the matching engine interpolation; inputs are seconds and are rounded to authored frames with strictly increasing keys. Translation and scale outputs become XYZ spatial channels. Rotation quaternions are decomposed to XYZ Euler degrees at each key and then blended per axis, which is a lossy approximation of glTF's spherical interpolation and can pass through gimbal-aligned intermediate poses. Cubic-spline samplers, morph-target animations and animations targeting nodes outside the imported scene are rejected or skipped rather than silently misrepresented.

glTF skins are baked at their rest pose. For each vertex the importer evaluates the weight-normalized sum of `joint_world * inverse_bind`, with joint world matrices taken from the glTF node hierarchy and expressed relative to the skinned node, whose own transform is ignored as glTF requires. The resulting positions are static: animated joints do not deform the baked mesh, and no runtime joint matrices are stored. Normal and other PBR texture maps, and emissive or occlusion terms, remain outside this importer.
